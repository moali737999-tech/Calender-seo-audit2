C1Critical

Canonical, sitemap, robots.txt and hreflang point to a domain that doesn't exist

Fixed · 5 OctCanonical is https://calendar.marketing, the robots Sitemap line is correct, and 0 of 220 sitemap URLs use the misspelled domain.

Every page's canonical uses http://calender.marketing: misspelled (calender) and on http. That domain has no DNS record. The same host appears in all 122 sitemap <loc> entries, the robots.txt Sitemap line, og:url, hreflang links and JSON-LD url fields. Google is being told the preferred copy of every page is a URL it cannot fetch.

curl https://calendar.marketing/ · robots.txt · sitemap.xml · nslookup<link rel="canonical" href="http://calender.marketing"/> Sitemap: http://calender.marketing/sitemap.xml <loc>http://calender.marketing/events/ramadan</loc> ← 122 of 122 URLs nslookup calender.marketing → Non-existent domain
Fix → Set NEXT_PUBLIC_SITE_URL=https://calendar.marketing in the Hostinger environment, and build metadataBase, sitemap.ts, robots.ts, hreflang and JSON-LD from that one constant. Then resubmit the sitemap in Search Console. Optionally register calender.marketing and 301 it to the real domain.
C4Critical

The Arabic version is invisible to search engines

Fixed · 5 Oct110 Arabic URLs live under /ar/ with lang="ar" dir="rtl", self-referencing canonicals, and en / ar / x-default hreflang on all 220 pages.

The header's "العربية" button sets a mmc-locale=ar cookie and re-renders the same URL in Arabic (lang="ar" dir="rtl", Arabic title and H1). Crawlers don't keep cookies, so every URL is indexed in English only. Arabic searches in Saudi, Egypt and the Gulf, likely the site's largest audience, can't find these pages.

curl /events/ramadan with and without the cookieno cookie: <html lang="en" dir="ltr"> Ramadan Marketing Campaign Ideas 2027 … Cookie mmc-locale=ar: <html lang="ar" dir="rtl"> أفكار حملات شهر رمضان 2027 … canonical (both): http://calender.marketing/events/ramadan ← same URL, no hreflang
Fix → Give Arabic its own URLs (/ar/events/ramadan, /ar/countries/…), the pattern the blog already uses. Each language gets a self-referencing canonical plus hreflang="en", "ar" and "x-default" alternates, and both go in the sitemap. The switcher then links to the other URL instead of setting a cookie.

M4Medium

Sitemap lastmod is the request time, not the edit time

Fixed · 5 Octlastmod varies per URL, and changefreq/priority are removed.

Static pages report lastmod = the moment the sitemap was fetched, so it changes on every request. Google ignores lastmod once it proves unreliable.

sitemap.xml fetched 11:45:01 UTC12 URLs <lastmod>2026-09-28T11:45:01.214Z</lastmod>
Fix → Use each record's real updatedAt, and fixed dates for static pages. changefreq and priority are ignored by Google and can go.

All HTML is served no-store and the CDN reports DYNAMIC, so each visit rebuilds the page. TTFB was 300–500 ms here and reached 3.2 s during the 122-URL crawl. Event, country and industry content rarely changes.
